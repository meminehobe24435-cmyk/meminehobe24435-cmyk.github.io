# 08 调试与问题（Debug & Problems）

> 从 `git log` 与代码反推站点在开发中「真实遇到/可能遇到」的问题。**能证实的标证据，不能证实的标【典型风险分析】**——绝不编造「线上出过什么 bug」。

## 一、从 git 历史反推的真实演进问题

`git log --stat` 给出 3 个 commit 的精确改动：

| commit | 时间(+0800) | 改动 | 反推的问题 |
| --- | --- | --- | --- |
| `e575bc6` | 2026-06-12 20:26:52 | 初始化：9 文件（含全部媒体 + 160 行 index + 400 行 CSS） | 一次性导入，非增量 |
| `81f14a6` | 2026-06-12 20:49:08 | `index.html +16`、`styles.css +36` | 补充联系方式区块 |
| `3e82fa0` | 2026-06-12 21:13:18 | `index.html +108`、`styles.css +94/-1` | 补充技能 + 奖项区块 |

**能证实的结论**：
- 站点在约 **47 分钟**内完成 3 次提交，是一个「先搭骨架 → 补联系 → 补技能奖项」的单会话快速迭代，而非长期项目。
- **二进制媒体从第一次提交就一次性入库**（`e575bc6` 含 5 个媒体文件），此后未再修改——说明视频/报告是「成品直接提交」，没有在 git 里经历转码迭代。
- 无 revert、无 fix、无 bug-fix 类提交 → **git 历史里没有可证实的「线上故障修复」记录**。

## 二、真实存在的问题（代码可证）

### 问题 1：媒体体积过大，移动端/弱网体验差（已证实）
- 证据：`binocular-vision.mp4` 27.0 MiB + `ch585-mouse.mp4` 11.5 MiB，视频合计 38.5 MiB；`binocular-vision-report.pdf` 10.1 MiB。
- 影响：移动数据网络下点开视频/报告代价高；GitHub Pages 无自建转码流水线。
- 缓解（已做）：`preload="metadata"`（`index.html:133,153`）避免首屏全量下载；`binocular` 用 H.264 保证兼容，`ch585` 用 H.265 压到 11.5 MiB。

### 问题 2：HEVC 视频的浏览器兼容性（已证实，属真实风险）
- 证据：`ch585-mouse.mp4` 编码为 `hvc1`（H.265/HEVC，二进制解析）。
- 影响：Firefox 等不原生支持 HEVC 的环境里，`<video>` 无法播放，只显示回退文本（`index.html:155`）。
- 定位：这是「压缩率 vs 兼容性」的取舍，但站点未提供 H.264 备源。

### 问题 3：视频无 poster 封面（已证实）
- 证据：`poster=""`（`index.html:133,153`），视频区背景 `#050607`（`styles.css:331`）。
- 影响：视频加载前是纯黑块，视觉观感差；也无法给 HR 一个「还没点播放就先看到画面」的钩子。

### 问题 4：站点展示项目与代码仓库脱节（已证实，最重要）
- 证据：站点 4 个项目均无 GitHub 仓库链接（`index.html:125-201` 无任何 `github.com` 外链）；而作者有 5 个公开仓库未被引用（见 07）。
- 影响：HR/面试官看完作品集，**无法一键跳转去验证代码**，削弱「可验证性」。

### 问题 5：移动端导航未折叠（已证实）
- 证据：`@media (max-width:760px)` 只改 `gap`，未做汉堡菜单（`styles.css:468-470`）；`body min-width:320px`（`:26`）。
- 影响：320~480px 窄屏下 4 个导航链接 + 品牌可能拥挤。

### 问题 6：SEO/无障碍进阶项缺失（已证实）
- 证据：无 favicon、无 Open Graph、无 canonical、无 JSON-LD（`index.html:3-12` 仅有 title/description）；无 `:focus-visible` 样式（`styles.css` 只有 `:hover`）；无 skip-link。
- 影响：社交分享无富卡片、键盘导航焦点不可见、搜索引擎结构化信息弱。

## 四、可讲的「调试方法论」（面试加分，结合真实工具）

虽然站点无运行时 bug，但可以讲「如果我要排查本站问题会怎么做」：

1. **网络/资源**：浏览器 DevTools → Network 面板，看 `styles.css`/`mp4`/`pdf` 的状态码与 `Range` 请求；`Lighthouse` 测性能/无障碍/SEO。
2. **视频起播**：确认 `moov` 前置，用 `ffprobe`/`mp4box` 读编码与 `faststart` 标志；本站已用二进制盒解析确认 `avc1`/`hvc1` 编码。
3. **移动端**：DevTools 设备仿真切到 320/375/768px，验证两个断点的布局塌缩。
4. **兼容性**：分别用 Safari/Chrome/Firefox 打开 CH585 视频，验证 HEVC 播放差异。

## 五、面试总结句

> 「这个站点的问题是静态站点常见的那几类：媒体体积大、HEVC 兼容性、缺 poster、以及最关键的——作品集没链接到代码仓库。git 历史只有 3 次当天提交，没有线上故障可讲；但这些问题我都能一条条说出『影响 + 改法』，例如给 CH585 视频加 H.264 备源、给视频补封面、在项目卡里加仓库链接。」
