# 13 代码质量审计（Code Review）

> 只审计、不改代码（遵守任务规则：只读 + 新增文档，不修改任何现有文件）。分四个维度：语义化、可访问性、SEO、资源管理。每项给「结论 + 证据 + 建议」。

## 一、总评

- **定位**：这是一个「一次性快速交付」的个人作品集，代码整洁、结构清晰、零冗余依赖，质量高于同类「拖拽生成的落地页」，但低于「长期维护的正式站点」。
- **核心优点**：语义化标签一致、样式集中且主题变量化、无障碍做了基础功课、无 JS 带来的健壮性。
- **核心短板**：SEO/无障碍只到「及格线」、视频体验（poster/兼容）有缺口、**最关键是内容与代码仓库脱节**（见 07）。

## 二、语义化（Semantic HTML）

| 检查项 | 结论 | 证据 |
| --- | --- | --- |
| doctype/lang | ✅ | `<!doctype html>`、`<html lang="zh-CN">`（`index.html:1-2`） |
| 语义分区 | ✅ | `<header>/<nav>/<main>/<section>/<article>` 使用正确（`index.html:14-279`） |
| 标题层级 | ⚠️ | `h1` 为「项目」（`:34`），语义偏弱——主标题应含姓名/定位关键词 |
| 标签选择 | ✅ | 项目卡/技能卡用 `<article>`，卡头用 `<span>` 合理 |

**建议**（仅记录）：`h1` 改为「尤译庆 · 嵌入式项目集」之类；`section` 可加更多 `aria-labelledby` 关联标题。

## 三、可访问性（Accessibility）

| 检查项 | 结论 | 证据 |
| --- | --- | --- |
| 语言声明 | ✅ | `lang="zh-CN"`（`:2`） |
| 导航/视频/联系标签 | ✅ | `aria-label`（`:15,16,45,133,153,265`） |
| 装饰层隐藏 | ✅ | `hero-grid` 用 `aria-hidden="true"`（`:31`） |
| 视频可访问名称 | ✅ | `<video aria-label="…">`（`:133,153`） |
| 视频字幕/文字稿 | ❌ | 无 `<track>`、无文字描述 |

| 动效降级 | ❌ | `scroll-behavior:smooth` 与 hover 位移未尊重 `prefers-reduced-motion` |

## 六、代码风格与可维护性

| 检查项 | 结论 | 证据 |
| --- | --- | --- |
| 缩进/格式 | ✅ | 统一 2 空格，HTML 属性换行一致 |
| CSS 组织 | ✅ | 变量集中、按区块分组、注释少但命名自解释 |
| CSS 重复 | ⚠️ | `.placeholder-panel` 的 `REPORT`/`TRACKING` 用两套近似规则（`styles.css:341-350`），可合并 |
| 响应式可维护性 | ⚠️ | 断点内靠「列出一堆选择器改 1fr」（`:489-496`），新增模块易漏改 |
| 无注释 | 中性 | 单页站点可接受，但「为什么 H.265/为什么无 JS」这类决策缺文档 |

## 七、审计结论（面试总结句）

> 「如果让我 review 这个仓库：语义化、无障碍基础、外链安全、资源预取都做对了，是合格的个人站点；要挑毛病，一是 h1 和 SEO 元信息偏弱、二是视频缺 poster 和 HEVC 备源、三是响应式靠堆选择器、四是 50 MB 二进制直接进 git。但最大的问题不在代码，而在**内容组织**——作品集没有链接到代码仓库，削弱了『可验证性』。这些我都能具体说出改法。」
