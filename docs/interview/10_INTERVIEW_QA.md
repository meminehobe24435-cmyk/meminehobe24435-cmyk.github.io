# 10 面试问答（Interview Q&A）

> 20~40 题，按星级划分，答案全部结合真实代码（行号/文件名/commit）。星级含义：★ 基础必答；★★ 高频进阶；★★★ 深度/压力追问。

## 一、为什么做作品集 / 内容组织（★ 必答）

**Q1（★）为什么做一个 GitHub Pages 作品集？**
A：嵌入式项目实物不好在简历里呈现，所以把 4 个项目的演示视频和 PDF 报告做成静态站，让面试官点开就能「看到」项目（`index.html:36-37`「HR 可直接查看演示视频与项目报告」）。站点 2026-06-12 搭建，3 次 commit 上线。

**Q2（★）你作品集里放了哪些东西？**
A：4 个项目（双目视觉、CH585 无线鼠标、自瞄装置、目标追踪）、2 个演示视频、3 份 PDF 报告、6 项技能、8 项奖项、联系方式。首页 stats 就是「4 项目 / 2 视频 / 3 报告」（`index.html:45-58`）。

**Q3（★★）你为什么把视频和 PDF 直接放 git 仓库，而不是图床/云盘？**
A：GitHub Pages 免费、自带 HTTPS + CDN、`.nojekyll` 让二进制原样发布（根目录有 `.nojekyll`）；代价是 50 MB 二进制进了 git 历史，clone 会全量拉取——这点我清楚，后续可改 Git LFS 或对象存储。

**Q4（★★）如果 HR 只有 10 秒，你这个站怎么留住他？**
A：首屏大标题 + 一句话定位 + 两个 CTA（「查看项目」/「查看代表报告」）+ stats 数字（`index.html:30-58`）；副按钮直接打开代表报告 PDF，让没耐心的人也能最快看到实质内容。

**Q5（★★★）你的站点 4 个项目，代码在哪？**
A：**如实回答**：站点上的 4 个项目目前只有视频/报告，没有直接链接到代码；我的代码在另外几个仓库——实习的 ESP32-S3 记录仪在 `esp-recorder`、无人机+STM32 四轮小车在 `uav-car-adhesion-platform`、杰理蓝牙工具集在 `ac632n-dev-tools`。站点还没把仓库链接补进去，这是我的待办（见 07）。

## 二、前端基础（★ 必答，站点真实用到的）

**Q6（★）你的站点用了什么技术栈？**
A：纯 HTML5 + CSS3，无 JavaScript、无框架、无构建工具（`index.html` 无 `<script>`，样式外置 `styles.css`）。部署走 GitHub Pages 直接发布 `main` 分支。

**Q7（★）CSS 里 `clamp()` 是做什么的？你在哪用了？**
A：`clamp(min, 理想值, max)` 让值在区间内随视口连续缩放；我用在 `h1/h2/h3` 字号上，如 `h1 { font-size: clamp(4rem,18vw,11rem) }`（`styles.css:155`），实现流式响应式字号。

**Q8（★）你的响应式是怎么做的？**
A：字号用 `clamp()` 连续响应；布局用两个断点离散响应——`@media (max-width:760px)` 把所有多栏 Grid 改单栏（`styles.css:463-512`），`@media (max-width:480px)` 隐藏品牌文字、按钮全宽（`:514-526`）。`body` 设 `min-width:320px` 保护极窄屏。

**Q9（★）`box-sizing:border-box` 为什么重要？**
A：让 `width` 包含 padding/border，布局更直观、避免盒模型溢出；我在 `*` 上全局设置（`styles.css:16-18`）。

**Q10（★）`preload="metadata"` 是什么？为什么用它？**
A：`<video>` 的 preload 策略之一，只预取时长/尺寸/首帧等元数据，不全量下载视频。我用它（`index.html:133,153`）避免首屏拉取 38.5 MB 视频，用户点播放才真正下载正文。

**Q11（★★）`backdrop-filter: blur(18px)` 是什么？兼容性？**
A：对元素**后方**内容做背景模糊（毛玻璃）。用在粘性导航（`styles.css:44-51`）。不支持的浏览器只是失去毛玻璃，导航仍可用——渐进增强。

**Q12（★★）为什么所有外链都带 `rel="noreferrer"`？**
A：`target="_blank"` 新开标签时，`noreferrer` 会（1）隐藏 referrer、（2）隐含 noopener 阻止 reverse tabnabbing（新页面不能通过 `window.opener` 操控原页）。用于 PDF/视频按钮（`index.html:41,145-197`）。

**Q13（★★）你站点完全没 JS，是刻意还是偷懒？**
A：刻意。站点交互（跳转/播放/发邮件）都被原生能力覆盖，引入 JS 只会加体积和复杂度；而且无 JS 意味着无首屏阻塞、无 SPA 白屏、SEO 直接可爬。如果要做懒加载/汉堡菜单，我会局部、渐进地引入原生脚本。

**Q14（★★）CSS Grid 和 Flexbox 你怎么选？**
A：二维布局（卡片矩阵、两栏项目卡、三栏联系方式）用 Grid（如 `.project { grid-template-columns: … }`，`styles.css:301-309`）；一维排列（按钮行、导航、证书条）用 Flex（`.hero-actions`、`.nav`，`styles.css:53-67,180-185`）。

## 三、部署流程（★ 必答）

**Q15（★）你的站点怎么发布上线的？**
A：`git push` 到 `meminehobe24435-cmyk.github.io` 的 `main` 分支，GitHub Pages 自动把根目录发布为站点（无自定义域名、无 Actions）。`.nojekyll` 关闭 Jekyll 保证 MP4/PDF 原样输出。

**Q16（★★）`.nojekyll` 不写会怎样？**
A：GitHub Pages 默认跑 Jekyll；没有 `_config.yml` 时通常也能构建，但 `assets/` 这类非 Jekyll 结构可能被忽略或路径被处理。放 `.nojekyll` 是显式声明「原样发布」的标准做法。

**Q17（★★）你的站点是 HTTPS 吗？怎么来的？**
A：是。`https://meminehobe24435-cmyk.github.io/`，实测 200。HTTPS 由 GitHub Pages 默认提供（并可强制），我无需自签证书或配 CDN。

**Q18（★★★）为什么不用 GitHub Actions 部署？**
A：本仓库没有构建步骤（无打包/压缩产物），直接发布源文件即可，Actions 的「先构建再发布」价值用不上，引入反而增加维护面——这是按需取舍，不是不会用。

**Q19（★★★）50 MB 大文件进 git，`git clone` 会不会很慢？你怎么看？**
A：会，二进制不压缩且 git 会保留历史版本，clone 需拉全量。承认这是当前权衡（图省事直接入库）；正确做法是 Git LFS 或把媒体放对象存储、仓库只存链接。这属于「我已知、后续会改」的点。

## 四、媒体与编码（★★ 高频，嵌入式候选人差异化加分）

**Q20（★★）你两个视频编码有什么不同？为什么？**
A：二进制解析显示 `binocular-vision.mp4` 是 H.264（`avc1`），`ch585-mouse.mp4` 是 H.265/HEVC（`hvc1`）。在相近分辨率下，HEVC 约 0.62 Mbps vs H.264 约 1.10 Mbps，省约 40% 码率。至于为何不同编码，最可能是来自不同录制/导出工具链，具体导出意图【待本人确认】。

**Q21（★★★）HEVC 做网页视频有什么坑？**
A：兼容性——Safari 原生支持，Chrome 依赖硬件解码，Firefox 默认不原生支持；所以 `ch585-mouse.mp4` 在某些浏览器只能命中回退文本（`index.html:155`）。正确做法是多 `<source>` 提供 H.264/WebM 备源。

**Q22（★★）静态 MP4 为什么能边下边播、拖进度条？**
A：靠 HTTP Range 请求 + `moov` 元数据里的「时间戳↔字节偏移」采样表；前提是 `moov` 前置（faststart）。这是渐进下载，不是流媒体协议。

**Q23（★★）10.1 MiB 的 66 页 PDF 会不会太重？**
A：对「点击后下载」可接受（不在首屏），但对移动端体验重；优化是提供压缩预览版 + 原件下载。

## 五、可访问性与 SEO（★★）

**Q24（★★）你做了哪些无障碍？漏了什么？**
A：做了 `lang="zh-CN"`、导航/视频/联系方式 `aria-label`、装饰层 `aria-hidden`（`index.html:2,15,31,133,265`）。漏了 `:focus-visible` 焦点样式、skip-link、视频字幕——这些是已知待办。

**Q25（★★）你的 SEO 现状如何？**
A：有 `title` + `meta description` + 语义化结构（基础可用）；缺 favicon、Open Graph、canonical、JSON-LD——社交分享无富卡片、搜索引擎无结构化信息。

**Q26（★★）`section` 和 `div` 的区别，为什么用 `section`？**
A：`section` 是「有主题的内容分区」，语义化标签利于无障碍与 SEO；`div` 无语义仅作容器。我的 6 个区块都有明确主题，故用 `section`（`index.html:30-279`）。
