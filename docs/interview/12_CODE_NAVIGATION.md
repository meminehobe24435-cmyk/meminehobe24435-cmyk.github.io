# 12 代码导航（5 分钟演示路线）

> 面试官/读者按这条路线 5 分钟走完仓库，从「宏观」到「细节」到「部署」，每一步标注看点与证据。

## 路线总览

```text
README.md ──> index.html ──> styles.css ──> assets/ 媒体 ──> 部署配置(.nojekyll / git)
  ① 宏观      ② 结构        ③ 样式        ④ 媒体/体积      ⑤ 上线机制
```

## 第 1 步（0:00-0:40）：README.md —— 建立全局认知

- 打开 `README.md`：确认「这是尤译庆的嵌入式开发实习生方向 GitHub Pages 作品集」。
- 看 `README.md:9` 的线上地址 `https://meminehobe24435-cmyk.github.io/`。
- 看 `README.md:11-16` 的项目清单（4 项）与 `README.md:18-23` 的文件结构。
- **看点**：README 极简，只交代「有什么」，不写「怎么部署/怎么改」——对作品集够用，对协作不足。

## 第 2 步（0:40-2:20）：index.html —— 结构走读

按顺序只看这几个锚点：

1. **head（`:3-12`）**：`lang="zh-CN"`、`viewport`、`title`、`description`、外链 `styles.css`。
2. **导航（`:14-27`）**：4 个锚点 `#skills/#projects/#awards/#contact`。
3. **首屏（`:30-60`）**：stats「4/2/3」+ 两个 CTA。
4. **项目区（`:125-201`）**：4 个项目卡，重点看第 1 个 featured 卡（`:131-149`）的 `<video preload="metadata">` 与双按钮。
5. **奖项/联系（`:203-279`）**：8 奖项 + 邮箱/电话/微信。
- **看点**：全文无 `<script>`、无 `<style>`（Ctrl+F 验证），证明「无 JS、样式外置」。

## 第 3 步（2:20-3:20）：styles.css —— 样式走读

- 顶部 `:root` 主题变量（`:1-14`）。
- 粘性导航 + 毛玻璃（`:44-51`）。
- 流式字号 `clamp()`（`:152-172`）。
- 项目两栏 Grid（`:301-309`）。
- 底部两个断点 `@media`（`:463-526`）。
- **看点**：一份 526 行 CSS 覆盖全部视觉，无预处理器、无 CSS 框架。

## 第 4 步（3:20-4:30）：assets/ —— 媒体与体积

- `assets/videos/`：2 个 mp4（27.0 MiB H.264 + 11.5 MiB H.265）。
- `assets/reports/`：3 个 PDF（10.1 MiB/66 页、1.64 MiB/9 页、1.23 MiB/14 页）。
- **看点**：媒体合计约 51 MiB，是仓库「50 MB」的主要来源；项目 → 资源的对应关系（见 03 第 10 节资源清单）。

## 第 5 步（4:30-5:00）：部署配置 + git 历史

- 根目录 `.nojekyll`（2 字节）→ 关闭 Jekyll、二进制原样发布。
- 无 `.github/`、无 `CNAME` → 直接发布 `main` 分支、默认域名。
- `git log`：3 个 commit（`e575bc6 → 81f14a6 → 3e82fa0`），均 2026-06-12，单会话搭建。
- **看点**：上线机制 =「push 到 main → GitHub Pages 自动发布」，无 CI 流水线。

## 5 分钟讲完的收尾句

> 「这个仓库就 9 个文件：1 个 HTML 定义结构、1 个 CSS 定义样式、5 个媒体承载项目证据、`.nojekyll` + `README` 负责发布与说明。它证明我能用最少的依赖把一个作品集快速、规范地上线，也说明我清楚二进制媒体在静态站里的取舍。」
